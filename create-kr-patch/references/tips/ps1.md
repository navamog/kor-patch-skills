# PlayStation 국소 사례

## PS1-001

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전에서 부팅 중 같은 RAM을 다시 적재한 뒤의 훅과 R3000A I-cache 상태.
- **사고 맥락:** 명령어 네 개로 이루어진 우회 코드가 16바이트 캐시 라인 두 개에 걸친 상태에서 부트 해제기가 같은 RAM을 다시 썼다. 캐시 라인별 갱신 상태가 달라 원본 호출 명령과 패치된 지연 슬롯이 섞여 실행되고 보존 레지스터가 오염됐다.
- **검증 근거:** 두 캐시 라인의 RAM·실행 명령 조합과 레지스터 결과를 대조해 혼합 실행을 확인했다. 우회 코드를 한 캐시 라인 안으로 줄이고 다음 원본 명령을 지연 슬롯으로 유지했으며 훅 본체는 캐시를 거치지 않는 KSEG1 별칭에서 실행했다.
- **확정 결과:** 다시 적재되는 패치 지점의 우회 코드를 한 캐시 라인 안에 넣고 비캐시 경로에서 실행해 갱신 전·후 명령의 혼합을 제거했다.
- **전이 한계:** 다른 훅은 재적재 범위·캐시 라인·별칭과 실행 순서를 확인해 캐시 무효화 또는 비캐시 경로를 선택한다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §4·§6, `references/strategy/runtime-assets.md` §2, `references/strategy/debugging.md` §3.

## PS1-002

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전의 Story SEQ에서 한 포인터가 다른 메시지 내부의 완전한 제어코드 묶음 시작점으로 진입하고, 추출 단계가 겹친 문자열을 합친 경우.
- **사고 맥락:** 중복 제거 뒤 남은 항목을 목록 순서로 다시 번호 매기면 다른 포인터 슬롯을 번역하게 된다. 내부 포인터가 가리키는 뒷부분을 별도 원문 블록으로 복사하면 전체 메시지는 번역돼도 해당 포인터로 진입한 화면에는 원문 뒷부분이 남았다.
- **검증 근거:** 추출 산출물이 원본 포인터 슬롯 번호를 유지하고 재삽입기가 이를 우선해 읽게 했다. 내부 포인터는 원문과 번역문 각각에서 대응하는 완전한 제어 구간 경계로 다시 계산하고, 각 포인터가 기대한 번역 뒷부분을 소비하는 합성 테스트 데이터로 확인했다.
- **확정 결과:** 문자열을 합쳐도 원본 포인터 슬롯을 재삽입 대상의 식별자로 유지하고, 내부 포인터가 가리킬 위치는 원문 바이트 거리가 아니라 번역 뒤에도 보존되는 구조 경계로 다시 계산해야 했다.
- **전이 한계:** 이 방식은 원문과 번역에서 같은 구조 경계를 다시 식별할 수 있을 때만 성립한다.
- **관련 판단 기준:** `references/strategy/text-extraction.md` §1.3·§4.1·§4.2, `references/strategy/reinsertion.md` §1.2·§2·§3.

## PS1-003

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전의 소형 데이터 불러오기 확인창 라벨과 실제 선택 배경 팔레트.
- **선택 맥락:** 제한된 팔레트의 작은 라벨에서 배경·외곽선·본문의 역할을 분리해야 했다. 이 자산은 세 역할에 해당하는 팔레트 인덱스만 쓰고 안티앨리어싱 없이 경계가 또렷한 픽셀 조판을 사용했다.
- **검증 근거:** 산출물이 선언한 세 인덱스 밖의 색을 쓰지 않는지 검사하고, 실제 데이터 불러오기 확인창에서 `예`·`아니오`를 표시했다. 선택 배경 위에서도 외곽선과 본문이 분리되어 판독됐고, 글자가 잘리지 않으며 인접 UI를 침범하지 않음을 확인했다.
- **확정 결과:** 세 팔레트 역할로 제한한 픽셀 조판이 실제 선택 배경에서 대비와 판독성을 유지하면서 글자 잘림과 주변 UI 손상을 피했다.
- **전이 한계:** 다른 UI는 실제 팔레트와 상태 배경에서 대비·잘림을 다시 확인한다.
- **관련 판단 기준:** `references/strategy/graphics-text.md` §2·§4, `references/strategy/font-strategy.md` §4, `references/strategy/build-and-verify.md` §5.

## PS1-006

- **관측 범위:** PlayStation 티어링 사가의 타이틀 로고 archive(4bpp tile 6장과 같은 이름의 별도 파일 6개)와 정착한 타이틀 화면의 표시 색.
- **사고 맥락:** tile 자체의 CLUT이 의미 없는 회색 램프였고 같은 index가 몇 픽셀 옆에서 다른 색으로 표시됐다. 여기서 "색은 런타임이 정하고 우리는 index만 고를 수 있다"고 판정했다. 그 전제 위에서 index 선택 규칙만 네 번 바꿨고(자리마다 가장 밝은 것, 후보 확장, 원본의 높이별 밝기, 구획별 목표색 최근접) 전부 획을 가로지르는 얼룩으로 나왔다. 전제가 틀렸으므로 그 안의 어떤 규칙도 균일한 색을 낼 수 없었다.
- **검증 근거:** 같은 archive의 짝 파일이 CLUT-only TIM이었고 선언 block이 palette 한 벌이 아니라 50벌이었다. 대응은 추정하지 않고 palette 앞쪽 절반과 뒤쪽 절반에 서로 다른 원색을 채워 넣어 실제로 부팅해 관측했다. 화면이 16x16 격자 체크무늬로 돌아왔고 경계 위치가 `palette 번호 = cy*가로칸수+cx` 대응과 일치했다. 넣은 값이 화면에 바이트 그대로 나와 표시까지 보정이 없다는 것도 같은 관측에서 확인했다.
- **확정 결과:** 이 자산은 그림을 16x16 칸으로 나눠 칸마다 별도 palette를 지정하는 구성이었다. 대응을 확정한 뒤에는 index를 고르는 대신 색을 직접 썼다 — 칸마다 배경이 가장 적게 쓰는 palette 항목을 필요한 수만큼 가져다 원하는 색을 적고, 밀려난 배경 픽셀은 그 칸 원본 palette 기준 최근접색으로 재배정했다. 배경이 이미 매끈한 램프라 한 칸이 16단계 중 6~10개만 써서 66칸에서 밀려난 픽셀은 37개였고, 표시 색은 지정값과 100% 일치했다.
- **전이 한계:** palette 벌 수와 구획 대응은 자산마다 다르므로 추정하지 않고 식별 값 주입과 실제 소비 경로 관측으로 확정한다. 항목을 가져오는 방식은 보존 대상 배경이 실제로 소비하지 않는 항목이 남아 있을 때만 성립하며, 재배정 변화량을 계량해 허용 여부를 판정한다.
- **관련 판단 기준:** `references/strategy/graphics-text.md` §2·§3, `references/platforms/ps1.md` §2, `references/strategy/runtime-assets.md` §2, `references/strategy/build-and-verify.md` §5.

## PS1-005

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전에서 한글 글리프가 처음 필요할 때 실행한 폰트 CD 적재와 배경 음악 상태.
- **사고 맥락:** BIOS 글리프 공급을 바꿔 한글 표시가 된 뒤에도, 첫 사용 시 디스크에서 폰트를 읽는 동안 음악이 중단됐다. 글리프 표시 성공을 폰트 경로 전체의 완료로 보기 쉬웠다.
- **검증 근거:** CD 명령 완료와 모드 복원 순서를 보완한 빌드에서도 첫 폰트 적재 때 음악이 중단됐다.
- **확정 결과:** 이 경로에서는 한글 표시와 첫 CD 적재 중 오디오 상태 보존이 별개의 판정이었다. 글리프 소비는 확인됐지만 오디오를 보존하는 적재 경로는 입증되지 않았다.
- **전이 한계:** 실행 중 새 자산을 읽는 경로는 표시 결과뿐 아니라 같은 시점에 유지돼야 하는 오디오·입력·화면 상태를 따로 확인한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md`, `references/strategy/reinsertion.md`, `references/strategy/runtime-assets.md`, `references/strategy/build-and-verify.md`.
